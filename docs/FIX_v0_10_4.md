# v0.10.4 — Motion Pro HTML graphics actually reach the video

## Root cause
`public/motion-pro/index.html` (the 171K generator) was bundled correctly and the compositor called it, but every frame
snapshot was drawn from an SVG `blob:` URL. Current Chromium/Android WebView marks a canvas drawn from a blob-URL SVG
`foreignObject` as **tainted**, so `VideoFrame(canvas)` / preview drawing failed and the HTML motion frames never made it
into the Studio preview or the MP4.

## Fixes
1. `divrizCapture` now uses a `data:image/svg+xml` URL (canvas stays clean -> VideoFrame + H.264 encode work).
2. Snapshot copies only styles that differ from UA defaults (pixel-identical, ~2.3x faster capture), and no longer waits on
   `requestAnimationFrame` (which stalls when the tab/app is in background and could hang export).
3. With burned-in captions ON, the template's own subtitle is left empty (no duplicate text line); unused placeholder subtitles are cleared.
4. `selector.ts`: "SaaS Explainer" and "Claude Motion" templates (fixed English demo UI: CloudBase, Users 8.4K, MRR...) are used only when the script is about software/apps/startups.

Verified in Chromium 157: 31 templates across all 8 ranges, 3 timestamps each, compositor with slide/fade/zoom/wipe transitions, VideoFrame + VP8/H.264 encode of real frames, unit tests (pro-plan, topics, three) pass.
